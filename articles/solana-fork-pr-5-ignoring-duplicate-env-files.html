The gap

The root .gitignore already covers .env and its documented variants, and those rules apply recursively, so every service inherits them. I verified that rather than assuming it:

apps/sdp-metrics-api/.env        IGNORED  (.gitignore:34)
apps/sdp-docs/.env               IGNORED  (.gitignore:34)

What no rule matches is a File Explorer duplicate. Copying .env on Windows produces .env copy, which carries identical secrets and is matched by none of .env, .env.local, .env.preview, .env.*.local, .env.docker:

.env copy                        NOT ignored
apps/sdp-metrics-api/.env copy   NOT ignored

Four lines fix it at the root, where the gap affects every service equally. #1 scoped the same idea to apps/sdp-metrics-api only.

After:

.env copy                            IGNORED
apps/sdp-metrics-api/.env copy       IGNORED
apps/sdp-metrics-api/.env.local copy IGNORED
apps/sdp-metrics-api/.env.example    not ignored   <- correct, meant to be tracked
apps/sdp-web/.env.local.example      not ignored   <- correct

Also confirmed no tracked file became ignored as a side effect: git ls-files | while read f; do git check-ignore -q &quot;$f&quot; &amp;&amp; echo &quot;$f&quot;; done returns nothing.

One of three PRs. Review all three; merge in this order:

  1. #2670: repo chore, independent (this PR)
  2. #2669: the service
  3. #2671: builds on #2669; sync after it merges

Pin files used in containers to LF, and ignore file-manager copies of .env.

  • On a Windows checkout with core.autocrlf=true, Docker builds from CRLF files, so entrypoint.sh gets #!/bin/sh\r and containers fail with exec /app/entrypoint.sh: no such file or directory. Seen during the MLH Fellowship on a fork of this repo, where sdp-web and sdp-docs restart-looped with exit 255.
  • New .gitattributes pins *.sh, *.bash, Dockerfile, Dockerfile.*, *.yml and *.yaml to LF. There's no * text=auto, so nothing else changes.
  • .gitignore now covers .env copy and .env - Copy variants, which hold the same secrets. .env.example stays tracked.
  • Existing Windows clones need to re-checkout these files.

Verification: on a fresh main checkout with autocrlf, CR bytes went from 6 to 0 in entrypoint.sh and 194 to 0 in apps/sdp-web/Dockerfile; all 90 matching tracked files are already LF; git check-ignore on 10 names. Not run: image rebuild. pnpm results are here.

What I learned and what I would carry forward

This was a small hygiene step in the public fork before the later upstream series. The PR remains open in the fork at the scan date.

The lasting lesson is specific to this record: A predictable .gitignore makes it less likely that machine-specific or sensitive configuration copies enter a change by accident. The next time I meet a similar problem, I would start by writing down the observable behavior, the constraints that define a correct result, and the smallest check that would distinguish a real fix from a plausible-looking change. For a design project, that means making requirements and drawings traceable.
