What I put in the pull request description

The text below is my original public description, preserved so the scope and evidence are inspectable. It is useful context for reading later commits and review comments; it is not a substitute for the final merged code.

pytest in apps/sdp-metrics-api currently runs nothing. It exits on a collection error:

tests/test_app.py:5: in <module>
    from app import (
E   ImportError: cannot import name 'MetricsUnavailableError' from 'app'

A collection error is directory-wide, so the 21 tests in tests/test_rpc_endpoint.py that #3 just added never execute. Run alone they all pass. Run with their sibling they do not run at all:

tests/test_rpc_endpoint.py alone   21 passed
whole directory                     1 error, 0 tests run

That is the worst shape a suite can take — one red line that reads like a single broken file, while silently withholding every result behind it.

Fix

test_app.py was written against an app.py exposing fetch_latest_overview, MetricsUnavailableError, _storage_options, _credential_provider and _profile_credential_provider. None of those exist in app.py today. Guarding the import converts the error into a module-level skip that names what is missing:

before:  1 error, 0 tests run
after:   21 passed, 1 skipped

The skip is not silent — -rs prints the reason and a pointer:

SKIPPED [1] tests/test_app.py:26: app.py does not expose the /metrics surface
these tests describe (cannot import name 'MetricsUnavailableError' from 'app').
See README.md and metrics.py - three definitions of /metrics disagree.

Why the file is kept, not deleted

It documents a contract that is still unsettled. Three sources in this one directory define /metrics differently, and app.py implements none of them:

sourcecontract
README.md:7newest row of analytics_cache, return response_json merged with holderCount, totalSupply, lastUpdated
tests/test_app.pyapp.fetch_latest_overview(table_path, region) → {&quot;data&quot;: &lt;overview&gt;}; 503 as {&quot;error&quot;:&quot;metrics_unavailable&quot;,&quot;message&quot;:…}
metrics.py:latest_metricsjoin polars_metrics × polars_metrics_values → {&quot;data&quot;:[…],&quot;date&quot;:…} — zero callers, dead code
app.py:43 (actual)/metric singular, raw pl.read_parquet dump

Consequences of that today, all on main:

  • GET /metrics returns 404
  • manual-test.sh:41 checks /metrics
  • test_endpoints.py:8 hits /metrics
  • infra/cdk/lib/metrics-api-stack.ts:91 publishes http://&lt;alb&gt;/metrics as the deployed URL

Unskipping this file is the acceptance test for whichever contract wins. I have a branch that wires /metrics to metrics.py:latest_metrics (the shape #1 shipped), deliberately unpushed — landing it would make /metrics answer 200 in a shape the README and this test file do not describe, which is worse than the current 404. That needs an owner's decision, not a guess, so it is out of scope here.

This PR only stops one import from hiding 21 results. It changes no application code.

Adds apps/sdp-metrics-api, a standalone Python service from the MLH Fellowship for Solana. It reports how active an SPL mint is, using Delta tables on S3 with a Solana RPC fallback. Background, AWS and open questions.

  • Routes: GET /rpc (count, cache state in X-Cache), GET /rpc/series, POST /insert, GET /healthz.
  • Writes and overrides are gated: /insert needs X-API-Token and answers 503 without a token or bucket. ?rpc= is off by default.
  • No default bucket, so no tie to any AWS account: set S3_INSERT_BUCKET and your own credentials.
  • Only adds files. Nothing calls it, and it isn't in docker-compose.yml, OpenAPI or the docs.
  • First Python in this repo: CI won't run its tests.
