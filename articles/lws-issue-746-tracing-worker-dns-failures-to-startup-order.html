My public comments and review activity

September 2, 2026Issue discussion

What happened:

  • Non-leader pod was scheduled on a node with an image cache hit while leader pod gets scheduled on a node with an image cache miss.
  • Application starts first on non-leader pod. DNS for leader does not resolve because pod is still in ContainerCreating state.

What you expected to happen: Workers should not start until leader is up

How to reproduce it (as minimally and precisely as possible): You can probably use a selector to force the leader pod onto a node to force a cache miss, while forcing the replica onto a node with a cache hit.
