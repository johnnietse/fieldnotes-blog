The spark

The useful question is whether a visitor can answer the practical event questions quickly, especially on a phone. A page can look polished and still fail if video, navigation, or deployment behavior is brittle.

What makes this one hold my attention is that the motivating question has a concrete surface: A Next.js event site presents schedules, registration, travel information, speakers, and conference details for first-year engineering students across Ontario.. That gives the work a way to be inspected. A reader can follow a requirement, trace its path into a file or drawing, and ask whether the artifact answers the original need. This is a more useful reason to care than the tool list by itself.

A project that began before its event

The history begins on October 10, 2023 with a Create Next App template. Event-site work resumes in May 2025 and continues through September. The dates tell a more useful story than pretending the site appeared fully formed: an early foundation sat in the repository, then an event deadline made its content and design concrete.

The README names my role as Webmaster for FYIC 2025. The conference brought first-year engineering students from more than 15 Ontario universities together for networking, workshops, and career-development programming. That identifies who the site had to help and why its information architecture mattered.

The difficult part was the path through the page

The hero component is the most frequently changed file in the commit history. June commits explicitly mention video loading, mobile autoplay, playback-loop transitions, play-button position, and a shooting-star animation. That is evidence of repeated browser-facing troubleshooting, though the short commit titles do not establish every root cause.

The useful before-and-after is the sequence: a starter template became an event page with content, navigation, and media that had to behave across screen sizes. The public history shows repeated attention to the most visible interaction, not a final device-by-device test report.

Deployment changed with the project

September 18, 2025 commits migrate from next-on-pages to OpenNext, remove the email API, and correct Wrangler configuration. The public README still links the Vercel demo, so I keep the configuration migration distinct from an assumption about the final live host.

The repository does not provide a reproducible browser/device matrix or final accessibility report. A stronger post should add those measurements instead of inferring them from responsive CSS.

What the project README actually specifies

The following is the project’s own public documentation. It is included as technical context, with links back to its original source.

FYIC 2025 Website

This website was developed using a forked template from the NextJS Tailwind Event Landing Page, which serves as a foundation for the landing page of FYIC 2025. The template is built with Tailwind CSS and Material Tailwind, offering flexibility and customization to suit the event's unique needs.

About FYIC 2025

The First Year Integration Conference (FYIC) 2025 brings together first-year engineering students from over 15 universities across Ontario. The event offers opportunities for networking with industry professionals, participating in interactive workshops, and learning more about career development, academic success, and diverse engineering pathways.

My Role: Webmaster for FYIC 2025

As the Webmaster for FYIC 2025, I am responsible for creating, maintaining, and optimizing the website. The goal is to ensure a seamless and user-friendly experience for participants, offering them easy access to event information, schedules, and other important resources.

Key Responsibilities:

  • Develop and maintain the event website.
  • Ensure the website remains secure and up-to-date.
  • Optimize functionality and accessibility for all users.
  • Troubleshoot and resolve any technical issues.
  • Monitor performance and implement improvements post-launch.

Features

  • Responsive Layout: Fully responsive design to ensure a smooth experience on both desktop and mobile devices.
  • Event Information: Easily accessible event details, schedules, and registration information.
  • Modern Design: Clean and minimalistic design with Material Tailwind and Tailwind CSS, ensuring fast loading and a great user experience.

Demo

You can view the live version of the website here.

Stack Tech Used

  • Next.js: React-based framework for server-side rendering and static site generation.
  • Tailwind CSS: Utility-first CSS framework to style the page.
  • Material Tailwind: Material design components for Tailwind CSS.

What I learned and what I would carry forward

The history shows a long template-to-event transition, a concentrated May–September 2025 build, many hero/video fixes, and a final move from next-on-pages to OpenNext with Wrangler deployment cleanup. The repository states that its Creative Tim template assets have limited-use rights, so this story links to the site and shows a generated architecture sketch instead of reusing those assets.

The lasting lesson is specific to this record: The useful question is whether a visitor can answer the practical event questions quickly, especially on a phone. A page can look polished and still fail if video, navigation, or deployment behavior is brittle. The next time I meet a similar problem, I would start by writing down the observable behavior, the constraints that define a correct result, and the smallest check that would distinguish a real fix from a plausible-looking change. For a design project, that means making requirements and drawings traceable. For a code contribution, it means connecting the issue, patch, review response, commit, and test output so a maintainer can follow the reasoning without reconstructing it from memory.

This is also why I keep the limits in the story. A portfolio entry is more credible when it identifies what was done, what the evidence confirms, and which environment or outcome still needs a fresh check. The public history is useful precisely because it lets a reader inspect those boundaries.
