What this is

The fellowship's Polars API work plus the platform-side integration that consumes it: 42 commits, 51 files. The service moved from a metrics endpoint that returned 500s to a cache-aware API deployed on ECS, read by the dashboard's Analytics tab, and runnable end to end on a Windows checkout.

Polars API

  • /metrics repaired: the 500 came from assuming partition_by returns a list; metric names now come from the catalog rather than being hardcoded.
  • /rpc honours the last-N contract, returns the token that was queried, and stops cache drift between requests.
  • SPL token transfer detection corrected; devnet is the default cluster.
  • The three spec endpoints are hardened against malformed input and against S3 or RPC failure, rather than surfacing a stack trace.
  • The date filter is pushed into the Polars scan instead of filtering after collection, and the median math is correct.
  • AWS credentials resolve through boto3, so a named profile, a session token, and container credentials all work; previously only static environment keys did.
  • Snapshot reads cover every prefix, and an empty result says "stale" instead of pretending there is no data.
  • The metric catalog is exposed, and /rpc accepts mint.
  • botocore is declared, and the container's worker constraints are documented.
  • The Docker image no longer copies the local virtualenv into the build.
  • The sdp-metrics-api capabilities are merged into this service, so there is one service to deploy rather than two.

Platform integration

  • The dashboard reaches the Polars services through a read-only proxy behind an allowlist, so the browser never holds the credentials and cannot write through it.
  • Analytics charts transactions on the cluster the platform actually issues on, counts Token-2022 holders, and shows Token Transfers for locally issued tokens with correct dates and a live devnet refresh.
  • "Deploy with Kora" is enabled in the token deploy dialog.
  • S3 failures in the checks are reported rather than swallowed.

Running it locally

  • One command brings the eight-service stack up from cold on a Windows checkout.
  • Surfpool runs under WSL on a fixed port, forked from devnet so state queries answer, with a watchdog that restarts a wedged validator and keeps chain state across restarts.
  • The Clerk organization and project linkage are seeded for local runs.
  • A checker exercises every dashboard tab's backing endpoint. It takes its key from SDP_API_KEY; there is no key literal in the repository.
  • The compose file passes the RPC rotation variables the ingester already supported.

CI

Six defects in the polars-api deploy workflow are fixed, and an ECS deployment workflow is added.

Verification

The stack was run end to end locally: every dashboard tab was checked against its backing endpoint, and the API was exercised against both S3-backed Delta tables and a live devnet RPC. Local runs surfaced three interaction bugs that no unit test had caught; those are fixed here.

Adds apps/sdp-metrics-api, a standalone Python service from the MLH Fellowship for Solana. It reports how active an SPL mint is, using Delta tables on S3 with a Solana RPC fallback. Background, AWS and open questions.

  • Routes: GET /rpc (count, cache state in X-Cache), GET /rpc/series, POST /insert, GET /healthz.
  • Writes and overrides are gated: /insert needs X-API-Token and answers 503 without a token or bucket. ?rpc= is off by default.
  • No default bucket, so no tie to any AWS account: set S3_INSERT_BUCKET and your own credentials.
  • Only adds files. Nothing calls it, and it isn't in docker-compose.yml, OpenAPI or the docs.
  • First Python in this repo: CI won't run its tests.

Co-authored with Arianna (@starry-ari). Waddah (@waldruupi) guided the data work.
