Solana PR #2670: pinning container line endings and ignoring env copies

This repository-hygiene PR pins LF line endings for container files and ignores duplicate .env copies created by file managers.

Before and after

Before

With core.autocrlf=true, shell and Docker files gained CRLF. The entrypoint shebang then included a carriage return; Docker could not find /app/entrypoint.sh. Copied .env files also risked being tracked.

After

The PR pins relevant shell, Dockerfile, and YAML files to LF and ignores copied .env variants while keeping .env.example. On a fresh checkout, entrypoint CR bytes went from 6 to 0 and Dockerfile CR bytes from 194 to 0.

Why this began

The change came from the same MLH Fellowship metrics-service work that later used a standalone Polars service.

This is a field note about one contribution trail: what I saw in the issue or pull request, how the change was shaped by review, what the public record says was tested, and what is still uncertain. The linked repository remains the authority for the current upstream state.

The spark

A Windows-created CRLF shebang can break a container entrypoint; small repository defaults prevent that environment mismatch from returning.

The practical value is in making this piece of project work reviewable. A small change has to fit the surrounding conventions, give maintainers enough context, and make its limits clear. The thread and diff are the evidence for that process; this post keeps the proposed scope and recorded outcome distinct.

This started as a runtime failure

The PR body traces the issue to Windows line-ending conversion. During the fellowship, sdp-web and sdp-docs restart-looped with exit 255 because the container could not execute the shell entrypoint.

The patch stays narrow: it pins only shell scripts, Dockerfiles, and YAML to LF, without a global text=auto rule. It ignores common file-manager copies of .env but leaves the example file tracked.

The before-and-after was measurable

The author measured entrypoint.sh changing from six carriage-return bytes to zero, and the Dockerfile from 194 to zero; ten candidate names were checked with git check-ignore. The PR says an image rebuild was not run. That means file-format behavior was verified, but a rebuilt container was not.

The lesson is to put a runtime file-format requirement in the repository rather than rely on each developer's Git settings.

Pin files used in containers to LF, and ignore file-manager copies of .env.

  • On a Windows checkout with core.autocrlf=true, Docker builds from CRLF files, so entrypoint.sh gets #!/bin/sh\r and containers fail with exec /app/entrypoint.sh: no such file or directory. Seen during the MLH Fellowship on a fork of this repo, where sdp-web and sdp-docs restart-looped with exit 255.
  • New .gitattributes pins *.sh, *.bash, Dockerfile, Dockerfile.*, *.yml and *.yaml to LF. There's no * text=auto, so nothing else changes.
  • .gitignore now covers .env copy and .env - Copy variants, which hold the same secrets. .env.example stays tracked.
  • Existing Windows clones need to re-checkout these files.

Adds apps/sdp-metrics-api, a standalone Python service from the MLH Fellowship for Solana. It reports how active an SPL mint is, using Delta tables on S3 with a Solana RPC fallback. Background, AWS and open questions.

  • Routes: GET /rpc (count, cache state in X-Cache), GET /rpc/series, POST /insert, GET /healthz.
  • Writes and overrides are gated: /insert needs X-API-Token and answers 503 without a token or bucket. ?rpc= is off by default.
  • No default bucket, so no tie to any AWS account: set S3_INSERT_BUCKET and your own credentials.
  • Only adds files. Nothing calls it, and it isn't in docker-compose.yml, OpenAPI or the docs.
  • First Python in this repo: CI won't run its tests.

Co-authored with Arianna (@starry-ari). Waddah (@waldruupi) guided the data work.

What I learned and what I would carry forward

This was intentionally independent from the service feature so it could be reviewed separately. The PR is closed without a merge recorded; its commit page and comments show the exact setup problem and attempted fix.

The lasting lesson is specific to this record: A Windows-created CRLF shebang can break a container entrypoint; small repository defaults prevent that environment mismatch from returning. The next time I meet a similar problem, I would start by writing down the observable behavior, the constraints that define a correct result, and the smallest check that would distinguish a real fix from a plausible-looking change. For a design project, that means making requirements and drawings traceable.
