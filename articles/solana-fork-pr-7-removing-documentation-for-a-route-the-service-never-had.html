apps/sdp-metrics-api has no /metrics route. app.py registers /metric (singular), which returns the raw values table, and nothing in the repository calls it. Four other places said otherwise, so GET /metrics has been answering 404 while the docs, both test scripts, and the deployed stack's own published URL all pointed at it.

The endpoint moved, in two directions

shapenow served by
analytics overview — stablecoins, holder counts, supply historysdp-api, GET /v1/data-products/analytics, reading Databricks
metric catalog — every id with its current value per providersdp-polars-api, GET /metrics, reading dev/mlh/polars_metrics_values

Established by looking at callers, not implementations:

  • nothing under apps/sdp-web references this service's /metrics; the dashboard reaches it only via METRICS_API_BASE_URL for /rpc and /rpc/series
  • analytics_cache appears nowhere in live code — only in .superpowers/sdd/* notes recording that path being built into sdp-api
  • metrics.py duplicates logic that sdp-polars-api ships and serves

Reading the three implementations had suggested a contract dispute to settle. Reading the consumers showed there was nothing to settle — this service simply no longer owns the endpoint.

metrics.py is annotated rather than deleted. The trap it poses is someone fixing a /metrics bug in the copy that isn't running; a docstring saying so is worth more than a silent removal, and the duplication stays visible.

Scope

No behaviour changes. No route added or removed. tests/test_app.py still describes a third contract and still fails to import — that is #6's subject, and this PR does not touch it.

Adds apps/sdp-metrics-api, a standalone Python service from the MLH Fellowship for Solana. It reports how active an SPL mint is, using Delta tables on S3 with a Solana RPC fallback. Background, AWS and open questions.

  • Routes: GET /rpc (count, cache state in X-Cache), GET /rpc/series, POST /insert, GET /healthz.

  • Only adds files. Nothing calls it, and it isn't in docker-compose.yml, OpenAPI or the docs.
  • First Python in this repo: CI won't run its tests.
